# portmatrix.sh

Матрица TCP/UDP доступности цели с этого хоста. Нужен, чтобы отличить блокировку по IP от блокировки по портам: если `ping` и 443 живы, а отдельные порты молчат — режут порты; если молчит всё — режут IP/маршрут или цель мертва.

## Зависимости

```bash
sudo apt install -y nmap netcat-openbsd dnsutils curl
```

`sudo` нужен для `nmap -sS/-sU` и `hping3`; остальное работает без root.

## Использование

```bash
./portmatrix.sh <IP> [iface|auto|direct]
```

| режим | когда |
|---|---|
| `auto` (по умолчанию) | ищет `wg*/tun*/ppp*/nordlynx*` |
| `direct` | **основной режим на docker-ноде xray**: туннельного интерфейса там нет, нода ходит через `eth0` (`freedom` outbound), т.е. это и есть egress VPN-клиента |
| `wg0` / `tun0` / … | привязать тест к конкретному туннелю |

```bash
./portmatrix.sh 80.96.58.253 direct
./portmatrix.sh 8.8.8.8 direct          # контроль: инструмент и маршрут в порядке
```

## Переменные

```bash
TCP_PORTS=22,443,8443 ./portmatrix.sh <IP> direct
UDP_PORTS=53,443,9443  ./portmatrix.sh <IP> direct
PROBE_PORT=8443        ./portmatrix.sh <IP> direct   # порт для 20 быстрых TCP-проб
```

Дефолты — 22 порта TCP (включая 1443/3443/5443/9443/11443/12443/13443) и 15 UDP.

## Вывод

1. `iface`, `route`, `egress` — куда реально идёт трафик и с какого IP; `egress` должен быть IP VPN-выхода.
2. `ping` — ICMP (часто режут и без блокировки, сам по себе не показатель).
3. `TCP` — состояния nmap; `TCP/<P> x20` — доля прошедших из 20 попыток (ловит вероятностный дроп).
4. `UDP` — состояния nmap.
5. `control` — 1.1.1.1:443 и udp/53; если и они не проходят, тест бессмыслен.

## Как читать

| состояние | значит |
|---|---|
| `open` | пара IP:port не блокируется |
| `closed` | пакет дошёл, хост ответил RST → фаервол цели или ничего не слушает, **не** сетевой блок |
| `filtered` | ответа нет → DPI/провайдер или DROP на хосте |
| `open\|filtered` (UDP) | ответа нет: открытый порт от дропа без payload'а не отличить |
| `x20` < 20/20 | вероятностный дроп (типично для ТСПУ) |

Уточнить UDP можно по ICMP (пришёл `icmp type=3 code=3` — пакет дошёл, порт закрыт):

```bash
sudo hping3 --udp -p 9443 -c 5 <IP>
```

## Ограничения

- Меряет только egress этой машины (ноды). Входящие порты ноды для российских клиентов так не проверить — нужен внешний взгляд (`check-host.net`) или реальный клиент.
- ICMP и RST могут резать анти-DDoS/rate-limit, тогда `filtered`/`closed` будут врать.
- Порты, работающие по UDP (hysteria/QUIC), надёжно проверяются только настоящим клиентом, не сканером.
